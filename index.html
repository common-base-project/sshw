🚀 SSHW

SSH 客户端自动登录包装器

📖 项目概述

SSHW 是一个优雅的 SSH 客户端包装器，专为简化远程服务器管理而设计。 它提供交互式菜单界面，支持自动登录、密钥认证、跳板机连接等功能，让 SSH 连接变得简单高效。

🎯 核心价值

  • ✨ 告别繁琐的 SSH 命令记忆
  • 🔐 安全管理多个服务器凭证
  • 📁 分组组织服务器，层级清晰
  • 🚀 一键快速登录，提升效率
  • 🔍 智能搜索，快速定位目标服务器

🏗️ 技术架构

技术栈

Go 1.23+ golang.org/x/crypto/ssh promptui (交互界面) gopkg.in/yaml.v2 ssh_config

核心模块

1
main.go - 程序入口，处理命令行参数，实现交互式菜单和服务器选择逻辑
2
config.go - 配置管理模块，支持 YAML 配置文件解析和 SSH Config 集成
3
client.go - SSH 客户端核心实现，处理连接、认证、终端交互和跳板机
4
log.go - 日志系统，提供统一的日志接口和格式化输出

工作流程

启动程序

解析命令行参数（-version, -help, -s），加载配置文件或 SSH Config

配置加载

按优先级顺序查找配置文件（~/.sshw, ~/.sshw.yml, ./.sshw 等），解析 YAML 结构

别名快速登录

如果提供了别名参数，直接查找对应服务器节点并登录

交互式选择

显示服务器列表，支持键盘导航、实时搜索和多关键词过滤

认证连接

尝试多种认证方式（密钥→密码→交互式），支持跳板机代理连接

会话管理

建立 SSH 会话，执行回调命令，监控终端大小变化，发送保活心跳

⚙️ 配置详解

配置文件位置

SSHW 按以下顺序查找配置文件（使用第一个找到的）：

  1. ~/.sshw
  2. ~/.sshw.yml
  3. ~/.sshw.yaml
  4. ./.sshw
  5. ./.sshw.yml
  6. ./.sshw.yaml
  7. ~/.ssh/config （自动回退）

💡 智能配置加载

如果没有找到 .sshw 配置文件，程序会自动回退到读取 ~/.ssh/config。这意味着即使你没有创建专门的 .sshw 配置，也可以直接使用现有的 SSH 配置！

你也可以通过 sshw -s 命令强制使用 SSH Config 文件。

配置项说明

配置项 说明 必填 默认值
name 服务器显示名称 ✅ -
alias 快速登录别名 ❌ -
host 服务器地址或 IP ✅ -
user 登录用户名 ❌ root
port SSH 端口 ❌ 22
password 登录密码 ❌ -
keypath 私钥文件路径 ❌ ~/.ssh/id_rsa
passphrase 私钥密码短语 ❌ -
jump 跳板机配置数组 ❌ -
children 子服务器组 ❌ -
callback-shells 登录后执行的命令 ❌ -

配置示例

基本配置

# 完整配置
- name: 生产服务器
  user: appuser
  host: 192.168.8.35
  port: 22
  password: 123456

# 使用密钥
- name: 开发服务器
  user: appuser
  host: 192.168.8.36
  keypath: /root/.ssh/id_rsa

# 带密码短语的密钥
- name: 测试服务器
  user: appuser
  host: 192.168.8.37
  keypath: /root/.ssh/id_rsa
  passphrase: mySecretPhrase

# 使用别名快速登录
- name: 快速开发机
  alias: dev
  host: 192.168.8.38

服务器分组

# 按环境分组
- name: 生产环境
  children:
    - name: Web 服务器 1
      user: root
      host: 192.168.1.10
    - name: Web 服务器 2
      user: root
      host: 192.168.1.11
    - name: 数据库服务器
      user: dbadmin
      host: 192.168.1.20

- name: 开发环境
  children:
    - name: 开发机 1
      user: developer
      host: 192.168.2.10
    - name: 开发机 2
      user: developer
      host: 192.168.2.11

跳板机配置

- name: 内网服务器
  user: appuser
  host: 10.0.1.100
  port: 22
  password: innerPassword
  jump:
    - user: jumpuser
      host: 123.45.67.89
      port: 2222
      password: jumpPassword

回调命令

- name: 自动化部署服务器
  user: deploy
  host: 192.168.8.50
  password: deployPass
  callback-shells:
    - cmd: "cd /app"
    - delay: 1000
      cmd: "ls -la"
    - delay: 500
      cmd: "echo 'Welcome!'"

🔒 安全最佳实践

⚠️ 安全提示

  • 优先使用 SSH 密钥：密钥认证比密码更安全
  • 保护配置文件：设置适当的文件权限（如 chmod 600 ~/.sshw.yml）
  • 使用密码短语：为 SSH 密钥添加密码短语保护
  • 避免明文密码：尽量不在配置文件中存储明文密码
  • 定期轮换密钥：定期更新 SSH 密钥和密码

推荐配置权限

# 设置配置文件权限（仅所有者可读写）
chmod 600 ~/.sshw.yml

# 设置 SSH 密钥权限
chmod 600 ~/.ssh/id_rsa
chmod 644 ~/.ssh/id_rsa.pub

# 设置 SSH 目录权限
chmod 700 ~/.ssh

🎓 高级特性

1. SSH Config 集成

使用 -s 参数可以直接读取 ~/.ssh/config 文件：

sshw -s

SSHW 会自动解析以下配置项：

  • Host（作为别名）
  • HostName（服务器地址）
  • User（登录用户）
  • Port（SSH 端口）
  • IdentityFile（密钥路径）

2. 多级跳板机

支持通过跳板机访问内网服务器：

工作原理：
  1. 先连接到跳板机（Jump Host）
  2. 通过跳板机建立到目标服务器的连接
  3. 所有流量通过跳板机转发

3. 自动化回调

登录后自动执行预设命令，实现工作流自动化：

callback-shells:
  - cmd: "cd /app"           # 立即执行
  - delay: 1000              # 等待 1 秒
    cmd: "git pull"          # 拉取最新代码
  - delay: 500               # 等待 0.5 秒
    cmd: "./deploy.sh"       # 执行部署脚本

4. 终端特性

  • 自动调整大小：终端窗口大小变化时自动调整
  • 保持连接：每 10 秒发送一次保活心跳
  • 完整支持：支持颜色、光标控制等所有终端特性
  • 交互式认证：支持键盘交互式认证方式

5. 加密套件支持

支持多种加密算法，兼容旧版 SSH 服务器：

aes128-ctr, aes192-ctr, aes256-ctr
aes128-gcm@openssh.com
chacha20-poly1305@openssh.com
arcfour256, arcfour128, arcfour
aes128-cbc, aes192-cbc, aes256-cbc
3des-cbc, blowfish-cbc, cast128-cbc

💡 技术实现亮点

1. 智能认证策略

SSHW 实现了多层次的认证回退机制：

1
SSH 密钥认证 - 优先尝试使用配置的私钥或默认的 ~/.ssh/id_rsa
2
密码认证 - 如果配置了密码，作为备用认证方式
3
交互式认证 - 支持动态输入密码或其他认证信息
4
终端密码输入 - 如果所有方式失败，提示用户手动输入密码

2. 层级菜单系统

  • 支持无限层级的服务器分组
  • 自动添加 "返回上级" 选项
  • 记住父级上下文，实现正确的返回导航
  • 美观的显示模板，突出活动项

3. 智能搜索算法

// 搜索逻辑
1. 合并服务器名称、用户名、主机地址为搜索内容
2. 支持空格分隔的多关键词搜索
3. 所有关键词都必须匹配（AND 逻辑）
4. 实时过滤，无延迟

4. 跳板机代理实现

使用 SSH 客户端嵌套实现跳板机功能：

  1. 建立到跳板机的 SSH 连接
  2. 通过跳板机的连接创建到目标服务器的 TCP 连接
  3. 在该 TCP 连接上建立新的 SSH 客户端连接
  4. 用户操作透明地通过两层连接传输

5. 终端状态管理

  • Raw 模式：切换终端到 Raw 模式，直接传递按键
  • 窗口监控：独立 goroutine 每秒检测窗口大小变化
  • 保活心跳：独立 goroutine 定期发送 keepalive 请求
  • 输入输出：异步处理，避免阻塞
  • 状态恢复：退出时恢复终端原始状态

❓ 常见问题

Q: 为什么无法连接到服务器？

A: 请检查：

  • 服务器地址和端口是否正确
  • 网络是否可达（可用 ping 测试）
  • 密钥文件路径是否正确
  • 密钥文件权限是否为 600
  • 用户名和密码是否正确

Q: 如何避免在配置文件中存储明文密码？

A: 推荐以下方案：

  • 使用 SSH 密钥认证，不配置 password 字段
  • 省略 password 字段，SSHW 会在需要时提示输入
  • 使用操作系统的密钥链管理工具
  • 设置配置文件权限为 600，限制访问

Q: 搜索功能不工作怎么办？

A: 搜索会匹配服务器名称、用户名和主机地址。确保：

  • 输入的关键词在这三个字段中存在
  • 多关键词用空格分隔
  • 所有关键词都必须匹配

Q: 可以同时打开多个 SSH 连接吗？

A: 可以。在不同的终端窗口中分别运行 sshw 即可建立多个独立的 SSH 会话。

Q: 支持 Windows 系统吗？

A: 理论上支持，但终端相关功能在 Windows 上可能需要使用 WSL 或 Git Bash 等环境。建议在 Linux/macOS 上使用以获得最佳体验。
